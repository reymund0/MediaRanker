## Required separately authorized IMDb calibration

Proposed target: a new disposable PostgreSQL 16 container with a dynamically assigned local port and a dedicated calibration directory in this worktree. Never use the original application's connection. One catalog writer, no artwork worker, no auto-restart, and no provider activation in the running application.

Proposed authorization envelope (not executed): exactly one HTTPS GET for each of `title.ratings.tsv.gz`, `title.basics.tsv.gz` and `title.episode.tsv.gz` at `datasets.imdbws.com`; total 3 sends, no redirects or retries. Cap each compressed file at 2 GiB, aggregate retained files at 6 GiB, each decompressed feed at 20 GiB, each feed at 50 million rows, each line at 1 MiB, process peak RSS at 2 GiB, owned temporary copy at 2 GiB, combined retained/download temporary disk at 8 GiB, and the isolated database volume at 60 GiB. Bound acquisition to 30 minutes and the complete acquisition/parse/stage/cleanup/load attempt to 90 minutes. Retain 15-second SQL timeouts, 5,000-row staging batches and 1,000-row cleanup/load output units. Stop and report upon any exceeded limit; do not silently increase it.

Retain the 8 Mi character aggregate batch cap alongside the 5,000-row and 1 Mi-character line limits; wide rows flush early. This bounds retained raw payload and SQL input size, not total process RSS. The full-feed run still requires an external 2 GiB RSS stop guard and observation of allocation/SQL expansion.

Keep the three bounded downloads for local replay so later measurements make no additional provider calls. Record actual compressed/decompressed sizes, row/filter counts, invalid-data incidence, peak disk/RSS, all stage times, transaction maxima, statement plans at full size, cleanup cutoff evidence and total duration. Verify cancellation and full replay from these local files against the same isolated database. If this proposed envelope is insufficient, present measured evidence and request a revised envelope before another live attempt. A logically incomplete but internally valid upstream publication cannot be detected from gzip integrity alone.

Only after successful full-size measurements and data/performance review should an operator choose and confirm a live finite profile. Current synthetic measurements and default test allowances do not certify one. No additional IGDB live sample is presently required to implement the disabled feature; any later live readiness check needs its own explicit bounds and authorization.
